# Audio, continuation and viewers — 8 October 2026

M4-02 now uses the existing Gallery-derived MediaExtractor/MediaCodec decoder for standalone recordings. Eight-second windows overlap by two seconds; decoded samples retain container timestamps, are downmixed and resampled to 16 kHz, then enter the existing LiteRT-LM audio API. Each interval is checkpointed under `audio-pcm-window-v1`. At most eight new intervals are prepared per worker execution; remaining coverage schedules a continuation. Cancellation retains compatible checkpoints and decoder failure offers a manual retry rather than endless automatic retries. Originals stay in their granted source folders.

Audio search returns multiple candidate intervals, with Media3 timeline playback, one-second lead-in and Return to match. Video candidates now contain actual frame thumbnails. Viewers occupy the activity's main content instead of a Compose dialog. The earlier stale search tree was traced to our ADB helper accepting Android's idle timeout and pulling old XML; the helper now rejects failed dumps. Hiding the continuously updating Media3 overlay allows a fresh tree exposing the viewer's controls. Full TalkBack acceptance and viewer restoration across configuration/process death remain separate gates.

The working Room v4 schema and LiteRT-LM 0.18.0 integration are retained. No additional native runtime or database migration is required. Codec support depends on the phone and source provider. An unavailable decoder retains filename search and Open with; the earlier short mono 16 kHz PCM WAV path remains as a limited fallback. There is no speech transcript or calibrated confidence.

## Reproduce

Build the debug app/test APK. Generate test assets with `python tools/create_media_continuation_fixtures.py` after generating the chapter video. Explicitly choose the generated KeepsBrowseTest tree in the app, containing only the seven prior fixtures. Push the two added recordings into that granted folder:

```powershell
adb -s SERIAL push app/src/androidTest/assets/audio/fixture-audio-long.m4a /sdcard/Download/KeepsBrowseTest/Media/fixture-audio-long.m4a
adb -s SERIAL push app/src/androidTest/assets/audio/fixture-audio-scenes.mp3 /sdcard/Download/KeepsBrowseTest/Media/fixture-audio-scenes.mp3
adb -s SERIAL shell am instrument -w -e keepsAudioLibraryTests true -e keepsContinuationTests true -e class dev.keeps.library.inference.DeviceAudioLibraryTest,dev.keeps.library.inference.DeviceLongVideoTest dev.keeps.library.test/androidx.test.runner.AndroidJUnitRunner
```

For fresh AAC continuation evidence the added recording must initially be unprepared; a cached rerun does not prove new-window preparation. Do not clear an existing user library to create this setup. The independent temporary video test always starts with nine new windows. Do not launch/search the activity during that test: its private test URI is intentionally outside ordinary SAF discovery. Older six/seven-file fixture tests retain their original strict setup and can skip on the expanded nine-file catalog; a skip is not a pass.
